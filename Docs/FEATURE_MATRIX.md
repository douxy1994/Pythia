# Pythia macOS / Windows Feature Matrix

| Feature | macOS Status | Windows Status | Notes |
| --- | --- | --- | --- |
| Main translation window | Implemented | Implemented, tested, and locally installed | Windows uses an adaptive Translate/History navigation shell instead of a fixed 320 px history sidebar. The translation page has IME-aware Enter handling, language/service controls, separate screenshot OCR and screenshot-translate actions, source copy/paste/remove-newlines/clear controls, vertically growing ordered result cards, copy-all, non-duplicating local favorite collection, a quick always-on-top action, and Windows SAPI speech. The settings shell is widget-tested at 100%, 125%, 150%, and 200% DPI; broader user-driven IME/multi-display checks remain. |
| Multi-service translation | Implemented | Implemented and tested; live providers partially verified | Windows has Google, Baidu, Youdao, OpenAI-compatible, DeepL, LibreTranslate, and installed `.pythia` providers, Credential Manager-backed secrets, a persistent multi-select/order panel, ordered result cards, and per-service failure cards. Credentialed built-in provider verification remains environment-dependent. |
| Language selection | Implemented | Implemented in code, x64 build verified | Windows uses persisted shared language codes; interactive verification remains required. |
| Smart mixed-language routing | Implemented | Implemented and tested | Windows `TranslationServiceRegistry.resolvedLanguages` mirrors the macOS mixed Chinese/English target-priority rule and feeds provider requests/history records. |
| Settings persistence | Implemented | Implemented in code, x64 build verified | Windows persists non-secret JSON settings and applies platform settings through native channels. Settings use eight macOS-aligned sidebar sections: General, Translation Services, Plugins, OCR, Shortcuts, Backup & Sync, Window, and About & Update. The bounded shell scrolls independently and is widget-tested at 100%, 125%, 150%, and 200% DPI; live platform-toggle verification remains required. |
| API key storage | Implemented with owner-only local credential storage | Implemented in code, x64 build verified | macOS stores service, proxy, WebDAV, and plugin secrets in an app-private `0600` file and does not call Keychain at runtime; Windows uses Credential Manager. Portable backups omit both. Live Windows Credential Manager verification remains required. |
| `.pythia` plugins | Implemented and runtime-tested | Implemented and tested | Both platforms validate the same Manifest/request/response contract, isolate each invocation in the bundled Node runtime, store secrets securely, and expose install/configure/test/disable/delete/reconvert management. Release packages do not include third-party plugins. |
| `.potext` migration | Seven installed plugins converted and checked | Partial | The WinUI client installs the converted `.pythia` packages and idempotently imports matching legacy Pot configuration values, moving secret fields into Credential Manager. Direct `.potext` package conversion remains in the legacy Flutter tool, not the WinUI UI. |
| History save/search/delete | Implemented | Implemented and tested | Windows has a dedicated history page with search, load, logical delete, clear, CSV export, portable JSON backup, and sync. Tombstones remain in the local store for cross-device deletion propagation. |
| History favorite/pin | Partial | Implemented and tested | Windows favorite changes are persisted and marked pending sync; live UI verification remains required. |
| Local/WebDAV backup and restore | Implemented with shared schema | Implemented in code, runtime verification pending | Both use schema-v1 portable settings/history at `/Pythia/settings/portable-backup.json`, pre-backup and merge history, preserve device settings, and omit secrets. macOS retains legacy `/pot` restore fallback only. |
| WebDAV history sync | Implemented in code | Implemented in code, runtime verification pending | Windows supports manual, periodic, local-change-debounced, and tray-triggered sync. Automatic schedules persist a positive value plus minute/hour/day/week unit. Corrupt remote data stops before local mutation, and a pre-sync snapshot is written. Live cross-device WebDAV verification remains required. |
| Global hotkeys | Implemented | Implemented; default registration verified locally | Windows records supported combinations directly in settings, canonicalizes aliases/order, rejects malformed or duplicate actions, registers show-window/selection/screenshot-translate/screenshot-OCR actions through `RegisterHotKey`, dispatches `WM_HOTKEY` to Dart, identifies the conflicting accelerator in native errors, and restores the previous runtime set when replacement fails. All four defaults register on the local Windows 11 acceptance machine; end-to-end action triggering and broader third-party conflicts remain user-driven checks. |
| Selection translation | Implemented | Implemented in code, runtime verification pending | Windows reads the focused control's selected TextPattern ranges through UI Automation without touching the clipboard, then falls back to simulated copy only when UIA is unavailable. Clipboard sequence checks prevent stale clipboard text from being mistaken for a selection. |
| Screenshot OCR/translation | Implemented with macOS Vision | Implemented in code, runtime verification pending | Windows hides Pythia, freezes the virtual desktop across monitors, supports forward/reverse drag selection plus Esc/right-click cancellation, recognizes the selected region with Windows Runtime `OcrEngine`, restores the window, and optionally translates. Image-file OCR is also implemented. |
| Status bar / tray | Implemented | Native WinUI implementation complete; live verification pending | Windows installs a notification-area icon; left-click restores the window; the right-click menu supports show, quick input translation, settings, history, WebDAV history sync, and quit. Actions dispatch directly to C# handlers. |
| System notifications | Native status feedback | Implemented in code, runtime verification pending | Windows startup/periodic WebDAV sync uses native information/error notifications and a persisted user switch; manual sync does not duplicate in-window feedback. |
| Text to speech | Implemented | Implemented in native Windows host; live audio check pending | The Windows result footer calls the built-in Windows Speech API through a tested MethodChannel contract. Compilation and channel tests pass; voice/language selection and audible output still need user verification. |
| Window behavior | Mostly implemented | Native scaffold complete, live verification pending | macOS applies `SMAppService.mainApp`; Windows writes/removes the current-user Run entry and the installer removes it during uninstall. Windows also persists close-to-tray, always-on-top, hide-on-blur, and window placement, clamps restored bounds to the nearest current monitor, enforces a DPI-aware minimum size, and requests the Windows 11 rounded Mica backdrop with an opaque readable fallback. |
| Update check | Implemented against Pythia GitHub | Implemented in code, signed runtime verification pending | Windows requires the exact Pythia Windows x64 EXE plus same-name `.sha256`, bounds the download, verifies SHA-256, asks for confirmation, launches the installer, and exits. Production Authenticode signing is required by the release checklist but cannot be validated on the intentionally unsigned local test build. |
| Release architecture/package gate | Implemented for macOS package script | WinUI x64 build and installer verified locally | The WinUI project targets x64 and publishes self-contained. The installer embeds the pinned Node runtime and emits a SHA-256 sidecar. Full install/upgrade/uninstall and sensitive-payload checks are repeated for the final local candidate; production Authenticode signing remains required. |

This matrix is intentionally conservative. A feature is not marked complete unless there is current code and verification evidence.
